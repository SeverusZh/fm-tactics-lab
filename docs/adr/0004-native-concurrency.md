# ADR-0004 原生并发与 counted-session

- 状态：已接受
- 日期：2026-11-12
- 决策者：仓库维护者

## 背景

上游 v1112 将原生宿主从每 64 场重建改为按能力协商的 counted-session，复用宿主到批次结束，并允许手动输入 1–256 路并行。本地分支需要保留 Agent 队列与客队战术池行为。

## 决策

- 合并上游 v1112 的宿主能力协商、逐场上下文清理与 worker 复用。
- 并行数 1–256 始终是合法输入；推荐值由 CPU 与可用内存计算。高于推荐值只警告；可用内存低于 2 GiB 或磁盘不足时默认 409，可显式覆盖；超过 256 属于范围错误。
- 单批次 FIFO 串行；批次内按 worker 分道，取消与续跑沿用现有语义。
- 旧宿主缺少 counted-session 能力时回退到每会话 64 场；执行力实验回退到隔离模式，并在 provenance 记录 `session_policy`。
- 高于推荐值显示非阻塞警告；UI 对 256 路要求二次确认。
- 资源预检按每路 1 GiB 加 2 GiB 保留估算；高于推荐值只警告，不阻塞 1–256 的手动输入。只有可用内存低于 2 GiB、磁盘不足或并行数超过 256 时返回 409；前两者可由 `allow_oversubscription=true` 覆盖。

## 验收

- 1、8、256 路各覆盖：提交、取消、续跑、失败明细与排队位置。
- fake engine 下同一输入与种子的比分、统计、执行力回执在 1/8/256 路一致。
- 能力协商测试覆盖 counted-session 与旧宿主回退。
- Windows 真机记录 8 路与 256 路的耗时、峰值内存与失败率；不得把 Linux fake 结果当作原生性能证据。
- 结果页与 README 必须区分“已实现”和“已实测到 8 路”。

## 后果

- 需要 Windows 真机验证复用后的比分、统计、执行力回执与取消/续跑。
- 宿主崩溃恢复、磁盘空间与超时检查必须保留。
- 并发提高会增加内存与 CPU 占用，UI 必须显示推荐值与警告。

## 备选

- 保持最多 4 路：无法满足更大并发需求。
- 多个批次同时运行：会与原生 DLL、存档读取和磁盘竞争，暂不采用。
- 取消手动上限：无法保护低内存机器。
