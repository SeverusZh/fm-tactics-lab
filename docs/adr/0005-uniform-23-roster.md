# ADR-0005 统一 23 人比赛名单

- 状态：已接受
- 日期：2026-11-12
- 决策者：仓库维护者

## 背景

主队样本为 23 人，客队与部分存档为 26 人。Issue #7 要求统一名单人数。维护者决定只允许 23 人，不实现 26 人分支。

## 决策

`MATCH_ROSTER_SIZE = 23` 是唯一合法比赛名单。所有来源在进入场景前按以下确定性算法归一化：

1. 读取来源球员列表、首发 11 人、替补顺序、队长、主罚与定位球优先级。
2. 首发保留来源 selection 的 slot 顺序；缺失或非法时，按位置覆盖顺序、ability 降序、source_uid 升序补齐。
3. 确保至少 1 名门将。存在第二名门将时优先进入替补；0 名门将时返回 `roster_missing_goalkeeper`。门将熟练度并列时取 ability 高者，再按 source_uid 升序。
4. 替补优先保留来源 substitute 顺序；不足 12 人时，按位置覆盖顺序补齐，再按 ability 降序、source_uid 升序。
5. 位置覆盖按完整 catalog 顺序：GK；SW、DC、DCR、DCL；DL、DR、WBL、WBR；DMC、DML、DMR；ML、MC、MR、MCL、MCR；AML、AMR、AMC、AMCL、AMCR；ST、STL、STR。每个位置组内按 ability 降序、source_uid 升序。
6. 取首发 11 人与替补 12 人合计 23 人。被移除的球员写入 `roster_trim.removed`，UI 显示姓名与数量。
7. 按 source_uid 过滤并重映射队长、主罚与定位球优先级。队长被移除时取第一位非 generated 的首发；若全部为 generated，队长留空。主罚列表为空时按位置资格与 ability 重新填充，跳过 generated；定位球优先级过滤后为空时使用默认顺序，跳过 generated。
8. 可用球员不足 23 人时，用 `generated=true` 的中性占位球员补齐。占位球员位置熟练度 15、可见属性 10、隐藏属性 10、伤病倾向 5、肮脏 5、左右脚 10/10；不得担任队长或第一主罚。
9. 输出 `roster_trim` 摘要：来源人数、移除名单、占位名单、重映射的主罚/队长/定位球引用。

## 兼容

- 旧 26 人方案加载时归一化为 23 人，并显示提示。
- 新方案只保存 23 人；不提供 26 人开关或隐藏路径。
- FMF、存档、AI 生成、战术池真实名单与结果统计共用同一实现。

## 测试

- 26→23、23→23、<23、只有 1 名门将、0 名门将、队长被移除、主罚被移除、定位球优先级被移除、全部首发为 generated。
- 同样输入重复归一化结果完全一致。
- 首发 11 人、至少 1 名门将、23 人上限与 source_uid 唯一性。

## 备选

- 可选 23 或 26：需要额外数据来源与双路径，被维护者否决。
- 只支持 26：样本主队不足 26 人，需要占位球员，且维护者明确选择 23。
