# ADR-0010 桌面自动更新的范围

- 状态：已接受
- 日期：2026-11-15
- 决策者：仓库维护者

## 背景

Tauri 桌面应用具备自动更新能力，但需要签名密钥、更新清单服务与回滚策略。当前仓库没有密钥托管、没有更新端点，也没有跨版本升级验证。安装包由 CI 构建并作为工件发布。

## 决策

- 本轮不接入自动更新，不引入 tauri-plugin-updater、不配置更新端点、不托管签名密钥。
- 发布路径为 CI 构建 NSIS 安装包；`release.yml` 在 tag 构建，把安装包附到 Release，验收证据以 30 天保留期的工件上传。
- 升级方式为用户手动安装新版本；安装与卸载由 NSIS 钩子停止旧进程并清理载荷。
- 桌面外壳只提供托盘、文件对话框、打开数据目录与外部链接；自动更新留待具备密钥托管与回滚验证后再决策。

## 后果

- 发布流程不依赖密钥托管，隐私与供应链风险低。
- 用户升级需要手动下载安装包。
- 后续接入自动更新需要先建立签名密钥管理、更新清单与降级验证。

## 备选

- 使用未签名更新：不可接受。
- 自建更新服务：需要长期运维与密钥托管，本轮不引入。

## 实现状态

- `src-tauri/tauri.conf.json` 不包含 updater 配置。
- `.github/workflows/release.yml` 构建并发布 NSIS 安装包。
