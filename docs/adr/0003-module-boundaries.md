# ADR-0003 模块边界与统一命令注册表

- 状态：已接受
- 日期：2026-11-12
- 决策者：仓库维护者

## 背景

当前服务端单文件同时承担校验、编码、任务、HTTP 与 Agent 路由；CLI 与 MCP 各自维护工具参数，容易漂移。维护者要求最大解耦，并让每个模块可以独立运行、测试和验证。

## 决策

- 采用模块化单体：`domain`、`application`、`ports`、`adapters`、`interfaces`。
- 依赖只能从外向内；`bootstrap.py` 是唯一组合根。
- 每个能力在 `registry.py` 定义一次，HTTP 路由、CLI 命令与 MCP 工具全部从同一份定义生成。
- 除 `/api/health`、`/api/version`、`/api/openapi.json`、`/api/docs`、静态资源与显式系统路由 `/api/shutdown`、`/api/events` 外，不允许手写业务路由。
- 模块之间通过显式接口与不可变数据通信，不使用模块级可变全局状态。
- 每个模块拥有独立测试；集成测试使用 fake engine，不依赖桌面应用。
- 契约测试必须验证每个能力在三个入口都存在，且输入/输出 schema 一致。

## 后果

- 新增能力必须先定义命令与输入/输出模型，再实现适配器与入口。
- CLI 与 MCP 的 schema 必须与 HTTP 契约同步，快照测试会阻止漂移。
- 组合根变厚，但业务模块变薄；禁止把业务逻辑放回接口层。

## 备选

- 继续单文件服务：无法满足独立测试与入口一致性。
- 微服务：本地单用户桌面应用不需要网络分区与独立部署。
