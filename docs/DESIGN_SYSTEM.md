# FM Tactics Lab 设计系统

## 设计读取

这是一个面向 FM27 玩家的数据密集型战术工作台。视觉方向为运动技术仪器，而不是通用 SaaS 仪表盘。颜色采用 FM 固有紫色作为信号色，深炭紫作为工作区，球场绿只用于正向数据。字体使用 Barlow 与 Barlow Condensed，强调数字、比分与表格的可读性。动效克制，只在状态切换与反馈中使用。

## 设计概念

“教练席仪器面板”：深色工作区像一块战术板，FM 紫色只在可操作与当前状态上出现，球场绿像场地标线一样标记正向数据，Condensed 数字让比分与指标像比赛记分牌。

概念必须体现在至少三处：左栏与顶部状态条的仪器化布局；Condensed 数字与细线表格；紫色信号与绿色数据的严格分工。

## 避免的默认套路

- 不使用通用深色紫渐变作为页面背景。
- 不使用玻璃拟态卡片堆叠。
- 不使用 Inter 作为默认字体。
- 不使用大量描边卡片；深度优先用背景层级与细线分隔。
- 不使用纯装饰性副标题、徽章或进度条。
- 不使用图标代替文字导航；图标必须有可访问名称。

## 颜色

主背景为深炭紫，表面通过变亮而不是投影来抬升。紫色是交互与当前状态，绿色是正向数据，琥珀是警告，红色是危险。中性色都向品牌紫偏移，不使用纯黑或纯灰。

对比度验证：

- 主文字 `#F2EEF7` 对 `--bg` 为 16.49:1。
- 次级文字 `#B9B0C7` 对 `--bg` 为 9.07:1。
- 辅助文字 `#8F859E` 对 `--bg` 为 5.41:1。
- `--on-accent` 白字对主操作 `#8B3DFF` 为 4.99:1，满足 AA 正文；主按钮必须使用该组合。
- 主文字 `#F2EEF7` 对主操作 `#8B3DFF` 只有 4.36:1，不得用于按钮文字。
- `--accent-text` 对 `--bg` 为 7.53:1，用于链接与强调。
- `--border-strong` 对 `--surface` 为 3.66:1、对 `--surface-raised` 为 3.40:1、对 `--bg` 为 3.91:1，满足非文本 3:1；输入框与选择器必须使用它。
- `--border` 对 `--surface` 只有 1.47:1，只能用于装饰分隔与表格线，不能作为输入框的唯一边界。
- `--pitch`、`--amber`、`--danger` 对 `--bg` 均高于 5.4:1。

紫色不用于正文；需要紫色文字时使用 `--accent-text`。

## 字体

- 展示与数字：Barlow Condensed，600/700。用于页面标题、比分、指标、表格数字。
- 正文与控件：Barlow，400/500/600。
- 等宽：JetBrains Mono，400/500。仅用于日志、ID、代码与路径。
- 字体通过 `@fontsource/barlow`、`@fontsource/barlow-condensed` 与 `@fontsource/jetbrains-mono` 自托管 woff2，打包进桌面资源；不依赖目标机器安装字体。
- fallback 栈：`"Barlow", "Segoe UI", system-ui, sans-serif`、`"Barlow Condensed", "Segoe UI", system-ui, sans-serif`、`"JetBrains Mono", "Cascadia Mono", Consolas, monospace`。
- 字体采用 SIL Open Font License 1.1；许可与来源写入 THIRD_PARTY_NOTICES.md，打包时保留 license 文件。

## 间距与形状

- 间距阶：4、8、12、16、20、24、32、40、48。
- 圆角：控件 8px，面板 10px，浮层 12px，标签 6px。
- 边框：1px `--border`；表格行分隔使用同一 token 的 50% 透明度。
- 深度：页面底、一级面板、浮层三层；不嵌套卡片。
- 阴影仅用于浮层与拖拽元素，使用带紫色调的柔和阴影。

## 布局与导航

- 左侧固定导航 200px，图标加文字；当前页用背景与紫色指示条标记。
- 顶部上下文条显示当前球队、存档、引擎状态与主操作。
- 主内容最大宽度 1440px，数据表可横向滚动。
- 底部运行条固定，显示种子、场数、并行数、主操作、进度与取消。
- 页面路由可深链；返回保留筛选、滚动与编辑状态。
- 小屏小于 1024px 时导航收为顶部栏，运行条换行；不隐藏主操作。

## 组件

- Button：primary、secondary、ghost、danger 四种；完整 default/hover/focus-visible/active/disabled 状态。
- Panel：标题、工具区、内容、底部操作；不使用多余副标题。
- DataTable：粘性表头、数字右对齐、行选中、空状态、批量操作栏。
- Field：label、hint、error、required 文本；错误使用 `aria-describedby`。
- SegmentedControl：用于有球/无球、随机/轮战、统一属性/真实名单。
- Sheet：战术池与设置使用右侧浮层，焦点陷阱、Esc 关闭、关闭后还原焦点。
- Toast：成功、信息、警告、错误；错误使用 `role="alert"`。
- Progress：批次进度、AI 生成进度；显示已完成、总数、速度、预计剩余。
- EmptyState：说明为什么为空、下一步操作、入口按钮。
- Skeleton：用于加载中的表格与战术板，保持布局稳定。
- Metric：比分、xG、控球、射门；数字使用 Condensed 与 tabular-nums。

## 页面蓝图

### 战术板

- 双阶段球场并排，当前阶段高亮；球衣可拖拽，也支持方向键换位。
- 右侧 inspector 显示球队指令、角色、职责与个人指令。
- 顶部显示球队切换、方案 JSON 导入导出、FMF 导入导出。
- 底部运行条常驻；战术池按钮在运行条右侧。

### 球员属性

- 左侧球员列表，右侧属性表；按技术、精神、身体、门将、隐藏/倾向、位置熟练度分组。
- 隐藏属性默认折叠且不参与全员统一属性；提供从参考球员复制与左右脚配对。
- 批量操作显示影响范围与撤销入口。

### 存档战术库

- 唯一存档导入入口；显示存档日期、构建、联赛与球队。
- 联赛表格列出球队、教练、两套战术、真实 AI 状态、导出与入池操作。
- “我的球队”卡片提供同步上一场阵容的首发 11 人与替补；导入后自动检测并提示，确认后覆盖，并提供撤销。
- 真实 AI 生成显示进度、失败原因与缓存状态。

### 实验结果

- 批次摘要、A/B 指标、配对差值、逐场表。
- 历史任务支持多选、全选、按状态筛选、批量删除与部分失败报告。
- 客队战术池卡片默认折叠，显示条目数、模式和名单来源，可展开查看。
- CSV 导出与单场事件查看。

### 设置与说明

- 引擎路径、兼容状态、数据目录、语言、并行推荐值、CLI/MCP 入口。
- 说明页只保留任务导向内容，不写营销文案。

## 交互状态

每个数据视图必须具备空、加载、错误、成功四种状态。异步操作在 100ms 内给出反馈；超过 400ms 显示进度或骨架。破坏性操作二次确认并说明影响。所有浮层使用碰撞感知定位，不溢出视口。

状态 token：

| 状态 | 视觉 |
| --- | --- |
| default | `--surface` 或 `--accent` |
| hover | `--hover`；主操作使用 `--accent-strong` |
| focus-visible | 2px `--accent-text` 焦点环，offset 2px |
| active | 主操作 `--accent-strong`，并轻微下沉 1px |
| selected | `--selected` 背景加左侧 2px `--accent-text` 指示条 |
| disabled | `--disabled-bg` + `--text-subtle`，保留可读性 |
| error | `--danger` 文本、图标与 1px 边框；输入使用 `aria-invalid` |
| warning | `--amber` 文本、图标与 1px 边框 |
| success | `--pitch` 文本、图标与 1px 边框 |

输入框、选择器与可交互自定义控件的边界使用 `--border-strong`，不得只用 `--border`。

## 可访问性

- 所有交互元素有 `:focus-visible` 焦点环，至少 3:1。
- 键盘可完成战术板换位、表格选择、浮层关闭与表单提交。
- 使用真实语义元素；模态与浮层焦点陷阱，关闭后还原焦点。
- 表格、分段控件、对话框、菜单遵循 WAI-ARIA APG。
- 错误通过 `role="alert"` 或 `aria-live` 宣布。
- 支持 200% 缩放、Windows 高对比度与 `prefers-reduced-motion`。
- `forced-colors: active` 下使用系统颜色：`Canvas`、`CanvasText`、`ButtonText`、`Highlight`、`HighlightText`，保留 1px 可见边框与焦点环。
- 不依赖颜色单独表达状态；状态同时使用图标或文字。

## 性能

- 路由级代码分割；战术板与结果页按需加载。
- 长列表虚拟化；表格只渲染可见行。
- 拖拽使用 pointer events 与 rAF，不用 React state 驱动每一帧。
- 图片与字体设置固定尺寸，避免布局偏移。
- 目标：LCP < 2.5s，CLS < 0.1，INP < 200ms；本地桌面环境不以此为绝对门槛，但必须测量。
